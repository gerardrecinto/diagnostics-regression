diagnostics-regression-lab

Devices send battery and performance numbers. This lab ingests them with Spark, removes anything private, compares one OS build to the last, and files a bug when a metric got worse. Synthetic data, one laptop.

The pipeline

ingestSpark Structured Streaming, JSON in, Parquet out, bad rows to a reject table
privacyField allowlist, salted device token, no email ever stored
aggregateExact dedupe, p50, p95, mean, std per build, app and metric. Hide groups under 20 devices
detectWelch test plus a minimum effect size, Bonferroni corrected
file bugsOne issue per regression, never twice. REST API and metrics alongside

Try it

Build 27A1 against 27A2, real output of the Python run. The same test runs here in your browser; regress.py is the source of truth.

Planted changes: Photos launch +18%, Maps battery +25%, Safari hang +2%. Measured on 1,800 samples per group, so the numbers wobble around the planted ones. Green line is your effect floor.

Decisions and trade-offs

All design-only: nothing here ran in production.

ChoseOverWhyCostsFlip when
Exact dedupe at aggregate timeStreaming dropDuplicatesWithinWatermarkIn my run, rows older than the watermark vanished: one rejected row went missing, and a six-file test lost three rows. A test now pins it.A shuffle over the whole day's data.The source is Kafka with a transactional sink, or ids live in a keyed store with a TTL.
Welch test on summary statsTest on every raw eventCost grows with groups, not events.Mean is skewed for latency data. Fine at 1,800 samples, weak under a few hundred.Small groups. Use Mann-Whitney or a bootstrap on raw samples.
BonferroniBenjamini-HochbergTwelve tests per build pair, and a false bug costs an engineer's time.Misses weak but real changes.Hundreds of groups per build.
5% effect floor plus a testSignificance aloneAt large n a 0.5% shift is "significant" and not worth a bug.Slow creep below 5% per build goes unseen.Add a trend check across several builds.
Salted hash tokenRaw device idDistinct-device counts still work for the k rule.Rotating the salt breaks joins across periods.Never needed for this use; keep the salt out of the repo in real use.
Fingerprint state fileSearch issues by labelWorks offline, no read permission needed.The file must be kept across runs.The DAG runs on several workers. Search issues by fingerprint.

Run it

Python 3.10 or newer and Java 17 or newer. About a minute on a laptop.

git clone https://github.com/gerardrecinto/diagnostics-regression-lab
cd diagnostics-regression-lab
python3 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
python -m diaglab demo
DATA_DIR=data/out uvicorn diaglab.api:app --port 8000
curl "localhost:8000/v1/regressions?baseline=27A1&candidate=27A2"
